# Данные и уведомления

## Что править руками

| Что | Где |
|---|---|
| Понедельник 1-й недели семестра | `WEEK1_MONDAY` в [Xlsx.kt](../app/src/main/java/ru/valov/raspisanie/Xlsx.kt) |
| Названия предметов по-русски | словарь `RU` там же |
| Строка поиска корпуса на карте | `CAMPUS` в [Schedule.kt](../app/src/main/java/ru/valov/raspisanie/Schedule.kt) |

Эталон разбора лежит в [fixtures/](../fixtures): xlsx и JSON, в который он обязан разобраться.
Его сверяет `XlsxTest`; эталон заморожен и при смене расписания не меняется.

## Откуда берётся расписание

При первом запуске приложение спрашивает источник: встроенное (xlsx из ассетов, класс 1/2)
или свой xlsx-файл выгрузки DNUI. Что бы ни выбрали, результат разбора ложится в один файл
`filesDir/schedule.json`, и экраны с уведомлениями читают только его
([Schedule.load](../app/src/main/java/ru/valov/raspisanie/Schedule.kt)). Встроенное
пересобирается после каждого обновления APK. Источник меняется в настройках, свой файл
при этом заменяется целиком.

Сервер для синхронизации — [server/](../server), его API — [api.md](api.md).

Разовые правки расписания (замены пар, выходные) задаются прямо в приложении,
в настройках, и живут в `Prefs.shifts`.

## Уведомления

Локальный `AlarmManager`, по одному будильнику на ближайшее событие — переживает
перезагрузку и переустановку. Вся логика выбора события в функции `nextEvent`
([Notifier.kt](../app/src/main/java/ru/valov/raspisanie/Notifier.kt)), её проверяет
[NotifierTest.kt](../app/src/test/java/ru/valov/raspisanie/NotifierTest.kt).

Два вида: вечерний дайджест на завтра и предупреждение о следующей паре за N минут
до конца текущей. Оба включаются и настраиваются в приложении. Вместе со вторым
приходит напоминание за 20 минут до начала первой пары дня и пары после перемены
длиннее 20 минут.

На Android 12+ в настройках приложения нужно разрешить «Будильники и напоминания»,
иначе Doze может задержать уведомление минут на 15. Приложение само предложит.
